**一、已确认的需求与决策**

| 项目 | 目标行为 |
| --- | --- |
| 身份 | 服务端创建身份，类似租户，并签发接入密钥；Agent 和 Android 只配置密钥，服务端由密钥确定身份，无需填写或提交身份 ID |
| 同身份 | 完成身份验证后，设备自动接入；同身份设备使用代理出口及 RDP 无需逐设备人工审批 |
| 跨身份授权 | 管理员将一台目标设备授权给某个身份，该身份下符合能力条件的设备均可使用，包括之后加入的设备 |
| 功能勾选 | 每条授权独立勾选“代理出口”“远程桌面 RDP”，可单选或同时选择 |
| 授权管理 | 支持新增、查看、编辑和删除；修改或删除后同步更新清单和连接权限 |
| 授权方向 | 目标设备 → 被授权身份；不授权目标所属身份的其他设备，也不自动建立反向共享 |
| 桌面 Agent | 默认出口及规则中的指定出口均提供下拉选择 |
| Android | 支持多条应用、IP/CIDR 等规则与组合条件；每条代理规则可下拉选出口 |
| Android 设置 | 按功能拆为独立配置页 |
| Android 兼容 | 保留 Android 8/9；按应用分流支持 Android 10+；旧系统保留现有功能及 IP 等非应用规则 |

“免授权”指免人工接入审批和同身份访问授权，服务端通过有效接入密钥验证归属。身份 ID 仅用于服务端内部关联和管理，客户端连接表单没有身份 ID 字段。目标设备也必须主动启用对应服务；自动接入不会自动开启手机网络共享、VPN 或 RDP 主机。

以下具体数据结构、接口名称和迁移方法是实施建议，未作为已实现功能描述。

**三、身份与设备接入设计**

将三个概念分开：管理后台账号用于登录和执行管理操作；连接身份用于设备归属；安装设备仍由现有公钥指纹识别。

建议服务端内部使用 `identityId`，管理界面称“身份”；客户端通过接入密钥获得服务端识别结果，身份名称只读展示。独立增加身份实体，不将现有 `owner_user_id` 直接重命名为身份 ID。因为当前 owner 可能只是审批管理员，同一个管理员审批的设备未必属于同一个人。

| 数据 | 建议字段/约束 |
| --- | --- |
| `identities` | `id`、`name`、`status`、允许的产品能力、创建/修改时间、`policy_revision` |
| `identity_access_keys` | `id`、所属身份、全局唯一的密钥摘要索引、有效期、撤销状态、创建人；仅创建时返回原始接入密钥，每把密钥固定关联一个身份 |
| `devices.identity_id` | 外键；迁移期可空，新模型生效后必须有已验证归属 |
| `identity_memberships` | 现有后台账号与身份的可见范围；首版由管理员维护，跨身份授权操作仍仅管理员可执行 |
| 设备认证记录 | 保留 fingerprint、installation ID、公钥、禁用/撤销状态；归属由服务端持久化，会话记录本次认证的 `access_key_id` 以支持撤销 |

管理员为身份生成接入密钥；设备只需填写 Relay 地址和这一把密钥，设备名称可自动生成。密钥使用服务端生成的高熵随机值，服务端通过密钥摘要索引定位记录并校验状态，再确定唯一身份；不要求用户从密钥中提取 ID，也不要求额外选择身份。同一身份可以签发多把密钥以便分别轮换或撤销，每把密钥只属于一个身份，不能修改密钥的身份映射。

接入密钥用于每次新建认证会话，包括自动重连；客户端安全保存后自动使用，无需每次输入。现有安装私钥仍由程序自动生成和管理，用来区分具体设备、验证持钥证明，不增加用户配置项。服务端验证有效接入密钥后才认可其身份，不能仅凭历史设备绑定跳过密钥有效性检查。

接入流程：

1. Agent/Android 在加密且验证服务器身份的连接上提交接入密钥、安装信息与公钥，不提交身份 ID。服务端按密钥摘要定位所属身份、校验密钥和身份状态，再发出 challenge。
2. 客户端自动用安装私钥签名。签名载荷绑定接入密钥摘要、服务端实例、双方 nonce、公钥、协议版本及能力声明，防止在挑战过程中替换凭据；身份始终取自服务端密钥记录。
3. 服务端验证设备持钥证明，登记前再次检查密钥及身份有效性；首次在事务中创建设备归属，之后检查已有绑定，并自动授予该身份允许且设备实际申请的能力。
4. 返回设备 ID、身份名称、有效能力、可用代理出口、可用 RDP 目标和策略版本。
5. 重连重新验证密钥、已有绑定与设备签名。更换同身份的有效密钥不改变设备 ID 或已有共享授权；已绑定设备换成其他身份的密钥时返回归属冲突，迁移归属由管理员执行，并失效旧会话。作为访问方的设备迁出身份后失去该身份获得的授权，迁入后按新身份重新计算；作为被共享目标的设备迁移归属时停用其对外共享，需管理员重新确认。

代理 client/exit、RDP controller/host 可在身份允许范围内随设备本地开关自动生效；身份策略收紧会撤回对应能力。公网 RDP 入口的 `rdp.public` 保持单独、显式的管理员控制，不随普通 RDP 主机能力自动开放。

密钥轮换建议采用“签发新密钥 → 设备替换 → 撤销旧密钥”，允许管理员控制过渡期。撤销或到期后，旧密钥不能添加设备或重连，已用该密钥建立的会话及相关 Relay/P2P/RDP 连接也进入撤销清理；同身份其他有效密钥不受影响。禁用身份则阻止该身份全部密钥和设备登录并清理现有会话。已撤销设备即使持有有效身份密钥，也不能通过重连自动恢复。凭据保存在受保护的本地存储，不出现在状态接口、日志、普通配置导出或 URL 中；认证失败不泄露其他身份信息。

握手建议新增版本 v4，在现有挑战签名中绑定接入密钥和能力声明；请求不增加 `identityId` 输入字段。v4 不支持时应报明确升级错误；兼容旧设备的策略见迁移部分。

**四、统一代理与 RDP 授权**

统一策略服务提供 `CanUseProxy(client, exit)` 与 `CanUseRDP(controller, target)`，并由同一策略生成候选清单。

```text
设备和身份有效 + 对应产品能力有效 + 目标服务已启用
    且（同 identity_id，或目标设备已授权给访问方身份且勾选了所请求的功能）
    ⇒ 允许使用
```

在线状态决定当前能否拨号；列表可以保留有权限的离线资源并标记不可用。授权不替代出口 ACL、私网策略、RDP 服务启用状态或远程操作系统的登录认证。

| 使用关系 | 代理出口 | RDP |
| --- | --- | --- |
| A1 → A2，同身份、对应服务已开启 | 自动允许 | 自动允许 |
| 身份 A 的设备访问 B1，B1 未授权给 A | 拒绝且不下发目标详情 | 拒绝且不下发目标详情 |
| B1 授权给身份 A，仅勾选代理；A1/A2 访问 B1 | 允许 | 拒绝 |
| B1 授权给身份 A，仅勾选 RDP；A1/A2 访问 B1 | 拒绝 | 允许 |
| B1 授权给身份 A，勾选两项；新加入的 A3 访问 B1 | 允许 | 允许 |
| B1 授权给身份 A，但 A1 访问未共享的 B2 | 拒绝 | 拒绝 |
| B1 授权给身份 A，但 B1 反向访问 A1 | 拒绝 | 拒绝 |
| 身份禁用、设备撤销或目标服务关闭 | 拒绝 | 拒绝 |

统一新增 `device_identity_grants`：`id`、`target_device_id`、`grantee_identity_id`、`features`、创建/修改人、创建/修改时间、可选到期时间和 `revision`；唯一键为 `(target_device_id, grantee_identity_id)`。`features` 使用受控枚举集合，首版为 `proxy.use`（使用代理出口）和 `rdp.connect`（连接远程桌面），对应 UI 的独立复选框。现有 `rdp_access_grants` 在迁移期用于 legacy 策略，不作为新模型的授权来源。

同身份访问采用策略判断；跨身份每台目标设备、每个被授权身份保存一条记录，不展开成身份内设备的 N×N 授权行。访问方身份必须从已验证的设备会话取得，不能信任开流请求自报的身份 ID。

后台设备详情增加“身份授权”列表，集中“跨身份授权”页也可管理同一批记录。列表显示目标设备、设备所属身份、被授权身份、已勾选功能、有效状态、更新时间及“编辑”“删除”。新增时选择设备和被授权身份，再勾选功能；一个设备可分别授权给多个身份，各记录互不影响。

编辑可修改被授权身份、功能和有效期；目标设备作为当前记录的固定资源，变更目标通过新增/删除操作完成。更换被授权身份在一次事务中撤回旧身份、赋予新身份；遇到重复 `(设备, 身份)` 提示编辑已有记录，不静默合并。至少勾选一项，清空功能时引导使用删除。未知功能值拒绝保存；目标尚不支持的功能禁选，暂时离线或已关闭但曾支持的功能可保留配置并显示当前不可用。

例如，将“办公室电脑”授权给“张三”，仅勾选“远程桌面 RDP”：张三现有及后来加入的设备都可在能力有效时连接这台电脑的 RDP，不能把它作为代理出口；张三也不会获得办公室其他电脑的权限。功能勾选不代表打开目标本地服务，也不包含目标设备管理权限或公网 RDP 入口权限。

必须同时接入这些路径：

- 认证返回和心跳中的代理出口、RDP 目标清单。
- 默认出口自动选择、显式指定出口、代理 TCP/UDP、测速。
- 代理 P2P 建立、候选交换、续租和恢复；移除“不同 owner 直接拒绝”的旧捷径。
- RDP Relay TCP/UDP、RDP P2P 建立、候选交换与续租。
- 管理 API 资源可见范围、撤销、禁用、归属迁移及过期处理。

目前 `authorizeExit` 对非空 owner 直接返回相等结果，`GetExitsForOwner` 也只扫描同 owner；只扩充数据库授权查询会导致“已有授权但列表不可见/仍被拒绝”。这些快速路径需要统一替换成同身份索引与跨身份授权索引，并按策略版本失效缓存。

编辑/删除时先原子更新策略并阻止新会话，再按“被授权身份 + 目标设备 + 被撤回功能”清理相关 Relay TCP/UDP、代理 P2P、RDP Relay/P2P 和恢复状态，刷新该身份所有在线设备的候选清单。取消 RDP 勾选仅撤回 RDP，已保留的代理授权继续有效；删除整条记录则撤回该身份对目标的全部显式共享。删除授权不删除设备或身份；重复删除须幂等，新增功能只在保存成功后生效。

连接清理需覆盖该身份的所有访问设备，不能只关闭操作时正在查看的一台设备。优先按上述范围关闭；若首版复用设备级会话失效，会使相关设备的其他连接重连，须在实施范围中明确并记录验证结果。在线对端收到撤销立即关闭；无法送达时，P2P 必须在有界租约到期后停止，不能声称离线控制通道也能瞬时撤销。具体时间上限在 M0 固定并纳入测试。

现有 RDP 目标集合替换接口直接写入数据库并返回，需要接入上述策略变更与会话清理流程，不能只依赖下一次续租发现变化。

`server` 虚拟出口没有普通设备身份，不能被“同身份”空值比较自动放行。建议作为系统资源，以同样的“资源 → 被授权身份”方式管理，仅支持代理功能；存储显式区分系统资源与真实设备，不能伪造设备外键。旧版本启用后的可用范围进入迁移审阅，不能默认对新身份全部开放。

建议管理员 API：

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/v1/identities` | 列出、创建身份 |
| `PATCH /api/v1/identities/{id}` | 名称、能力范围、启停 |
| `POST /api/v1/identities/{id}/access-keys` | 为指定身份签发接入密钥；路径中的身份 ID 仅用于后台管理 |
| `DELETE /api/v1/identities/{id}/access-keys/{keyId}` | 撤销接入密钥并清理使用它的会话 |
| `PUT /api/v1/devices/{id}/identity` | 管理员绑定/迁移归属 |
| `GET /api/v1/device-identity-grants` | 授权列表，可按目标设备、被授权身份、功能筛选 |
| `POST /api/v1/device-identity-grants` | 新增设备对身份的授权及勾选功能 |
| `PATCH /api/v1/device-identity-grants/{grantId}` | 编辑被授权身份、功能或有效期，带 revision |
| `DELETE /api/v1/device-identity-grants/{grantId}` | 删除授权并撤回对应权限，带 revision |

所有授权管理接口仅服务端管理员可操作，审计记录保留编辑前后值及删除事件。编辑和删除应带 revision 或等价并发控制，避免两个管理页面覆盖彼此的授权。已有按控制设备替换 RDP 目标的接口在 legacy 范围兼容，新身份模型下不再用于写授权，防止重新引入设备对设备的权限语义。

有效权限视图区分“同身份自动允许”和“管理员显式授权”；自身身份不需要创建共享记录，创建时提示已自动允许。限制同身份服务应关闭目标服务或收紧身份能力。被授权身份禁用后共享不生效，设备迁出该身份即失去其共享权限；身份删除时删除对应授权并保留审计，目标设备删除时删除其授权，均不影响其他资源。

**五、桌面与 Android 共用的出口选择**

扩展现有 `ProxyExit`，提供稳定设备 ID、名称、归属身份显示名、在线状态及授权来源；RDP 目标使用相同显示约定。只下发同身份或已获授权的资源摘要，不下发全体设备、内部 RDP 地址或后台凭据。

桌面 `Agent` 在认证与心跳中缓存清单，经 Bridge、Web API 与 Windows 绑定提供给 UI；默认出口、规则编辑器和测速入口使用同一份候选。RDP 主机清单同步呈现跨身份已授权目标。

下拉交互：

- 显示“设备名 · 身份 · 在线状态”，保存稳定 ID；同名设备显示短 ID 辅助区分。
- 默认出口提供“自动选择”，严格仅在一个可用且已授权出口时生效；多个出口要求用户选择。
- 规则出口提供“跟随默认出口”与具体设备；DIRECT、REJECT 隐藏出口项。
- 已选设备离线保留原选择并标记离线；授权撤销或设备删除保留本地占位及错误，不能静默改选其他出口或 DIRECT。
- 当前设备默认不列为自己的远端出口；本机出网使用 DIRECT。
- 首次接入且没有出口时，控制会话仍可建立，UI 显示“暂无可用出口”，不陷入必须先选出口才能获取清单的循环。
- 清单刷新不会覆盖正在编辑的选择；名称变化不影响 ID；断线时缓存显示为未确认状态。

出口切换影响新流；存量连接保持原出口直至关闭或用户重连。规则更新也采用这一原则；权限撤销、身份禁用与策略收紧属于必须清理的例外。

**六、Android 规则模型与行为**

复用 `agent/routing` 的匹配、校验、优先级和动作语义。新增 Android 专用的应用包名选择器及流元数据；不把包名混成 Windows 进程路径，也不把 Go 路由逻辑复制到 Kotlin。

| 条件/操作 | 支持范围 |
| --- | --- |
| 应用 | 一个或多个包名；支持搜索、多选、已卸载提示；Android 10+ VPN 流量 |
| IP | IPv4/IPv6 精确地址、CIDR；与域名条件的关系明确区分 |
| 域名 | 精确域名、后缀/现有通配规则；只使用确知的域名信息 |
| 端口 | 单端口、范围、多个端口 |
| 协议 | TCP、UDP、全部 |
| 组合 | 同字段多个值为 OR，不同字段为 AND |
| 动作 | PROXY、DIRECT、REJECT；PROXY 可指定出口或跟随默认 |
| 列表 | 多条规则、启停、复制、排序、删除、命中计数、默认动作 |

从上到下第一条启用且匹配的规则生效。无匹配时执行默认动作；默认建议 PROXY + 用户选择的默认出口。全局代理、全局直连、按规则分流三个模式使用现有引擎语义。

例如：聊天应用 → 家中出口；办公应用 AND `10.0.0.0/8` → 公司出口；`192.168.0.0/16` → DIRECT；UDP 443 → 指定出口；其他流量 → 默认出口。顺序由用户调整，不额外插入隐藏优先级。

VPN 的应用白/黑名单只控制流量是否进入 VPN；规则列表决定进入后的处理。应用被排除时显示其应用规则不会生效。显式 SOCKS5/HTTP 入口首版支持目标、端口、协议等规则；不能把调用本地代理的应用归属识别等同于 VPN 应用识别，无法可靠识别时展示限制。

**应用元数据链路是首个技术验证项**

现有 Hev → SOCKS5 链路只向 Go 暴露回环连接及目标；对回环连接查询 UID 会识别到 RelayProxy/Hev，而非原始应用。`addAllowedApplication` 也只能选择 VPN 覆盖范围，不能为多个应用指定不同出口。[Android VPN 文档](https://developer.android.com/develop/connectivity/vpn)

Android 10/API 29 起，活动 `VpnService` 可通过 `ConnectivityManager.getConnectionOwnerUid()` 查询 TCP/UDP 原始连接归属，可能返回未知 UID。规划据此把按应用分流限定为 Android 10+。[Android API 文档](https://developer.android.com/reference/android/net/ConnectivityManager#getConnectionOwnerUid(int,%20java.net.InetSocketAddress,%20java.net.InetSocketAddress))

建议验证以下主方案：

1. 给固定版本 Hev 增加最小原始流回调，获得 TUN 内源/目标地址、端口、协议和流生命周期；在域名/Fake-IP 转换前查询 UID。
2. Kotlin 将 UID 映射为包名集合，按流缓存；Go 接收原始流元数据。共享 UID、多用户/工作资料、未知 UID 和应用卸载必须显式处理。
3. 为每个原始流建立不可猜测、绑定运行时代次且短期有效的 flow token，通过专用内部转发契约绑定到 Go 的拨号上下文。TCP 与 UDP 均需要准确关联；UDP 必须区分不同应用访问同一目标的情况。
4. VPN 固定使用独立内部入口，不再复用用户 SOCKS5 监听端口。内部协议可验证每流 token，外部 SOCKS5/HTTP 无权提供应用归属。优先验证每个 UDP 原始流独立 association 或等价可靠绑定，不按目标地址猜来源。
5. 所有流量最终进入 `RoutingDialer`；PROXY 复用 Relay/P2P，DIRECT 通过已绑定物理网络的本地 socket，REJECT 在拨号前拒绝。

上述 Hev 回调与关联协议尚未实现或验证；M0 必须给出 TCP/UDP 双栈实测和维护成本，再固定协议。若无法正确保留归属，重新选择支持原始流元数据的 TUN 接入方案，不能只完成应用选择 UI 就宣称支持应用分流。已有构建脚本每次重新解压依赖，因此原生修改必须以仓库内可重复应用的补丁及校验进入两个构建脚本。

共享 UID 无法可靠区分具体包时，界面提示这些包共享归属，按同一应用组处理。存在启用的应用规则但某条流归属未知时，默认拒绝该流并记录原因，避免误走另一个身份出口；不把未知 UID 当作某个应用。可以后续增加显式的未知应用策略。Android 8/9 禁止启用包含应用条件的规则，并保留提示，不默默去掉应用条件使规则范围扩大。

**Mapped DNS 与 IP 规则必须一起设计**

当前 VPN 将 Fake-IP 恢复为域名交给出口解析。现有规则引擎不会为了 IP 规则主动解析域名，因此只接入该引擎会导致很多普通域名连接匹配不到 IP/CIDR。

计划引入路由前解析适配层：纯 IP 请求直接匹配；域名请求在确需真实 IP 判断时，经明确配置且获授权的 DNS 出口取得真实地址，将原始域名和真实 IP 同时交给引擎。DNS 出口默认跟随默认出口，也可显式指定，避免“先知道业务出口才能解析、先解析才能决定业务出口”的循环。

解析与匹配后的拨号必须绑定同一个真实 IP，不能在业务出口重新解析得到另一个地址使 IP 规则失效。多 A/AAAA 候选、重试和 Happy Eyeballs 需逐候选应用同一规则语义；不能通过切换地址绕过 REJECT。DNS 缓存按身份、DNS 出口、网络代次及 TTL 隔离；识别出的 Fake-IP 不参加真实 IP/CIDR 匹配。内网域名需要能解析该域名的 DNS 出口。

DNS 默认随代理通道访问，不在失败后静默改走系统直连 DNS；DIRECT 规则使用什么解析路径也须在 DNS 页明确显示。系统 Private DNS、应用 DoH/DoT 和仅观察到 IP 的连接可能没有可证明的域名，此时只评估可用元数据，不能通过反查猜域名。IP 与域名规则冲突、IPv6、DNS64、缓存刷新和两个出口访问同域名列入 M0/M5 验证。

**七、Android 页面拆分与配置保存**

首页保留连接身份、运行状态、当前默认出口、VPN/本机代理/网络共享独立开关及错误摘要。设置首页仅列导航项与当前摘要。

| 页面 | 配置内容 |
| --- | --- |
| 连接与身份 | Relay 地址、接入密钥、设备名称；连接成功后只读显示服务端识别的身份名称；高级项含传输、端口、TLS |
| 出口选择 | 默认出口、在线状态、身份归属、授权来源；首页也可快捷切换 |
| 分流规则 | 模式、默认动作、规则列表；规则编辑独立页，含应用/目标/端口/协议/动作/出口 |
| VPN 与应用范围 | VPN 覆盖范围、应用选择、权限状态及系统兼容提示 |
| 本机代理 | SOCKS5/HTTP 开关、监听端口 |
| 网络共享 | 出口服务及出口 ACL，包括是否允许目标私网 |
| 网络与连接策略 | Wi-Fi/蜂窝优先级、自动切换、P2P 与省电策略 |
| DNS | 解析出口、Mapped DNS 与真实 IP 规则说明、兼容状态 |
| 诊断与关于 | 授权错误、规则命中、实际出口、Relay/P2P 路径、日志和版本 |

复用 Kotlin 原生 Activity 和现有视觉组件，首版不为分页引入整套新 UI 框架。`SettingsActivity` 改为目录；复用 `VpnAppSelectionActivity` 的选择能力，区分“VPN 范围选择”和“规则应用选择”。

配置增加 schema version、受保护的接入密钥引用、规则配置、DNS 路由配置；不增加需要填写的身份 ID，服务端返回的身份摘要仅作展示缓存，不能用于认证。各页使用分组更新与 revision 校验，保存前读取最新配置合并本页字段；禁止每个子页用旧的完整 `ExitConfig` 覆盖其他页或服务运行意图。校验失败保留原运行配置及本页编辑内容。

规则/默认出口变更尽量原子更新，只影响新流；VPN 应用范围变化重建 TUN；接入密钥/地址/物理网络变化重建对应运行时并重新认证。具体变更需要重连时，保存入口明确提示影响。屏幕旋转、后台恢复、返回取消、快速连续保存不能丢失规则或重复创建 Core。

**八、迁移与兼容**

1. 先备份数据库及配置，引入可重复执行的 schema migration；新增表/字段不先删除旧 owner、设备密钥或授权数据。
2. 管理后台提供旧设备归属清单。管理员确认哪些设备属于同一身份；可以按旧 owner 生成候选分组，但不能把审批人相同自动当作同一人。
3. 未映射设备在明确的 legacy 模式中维持原有策略；legacy 与新身份设备之间默认隔离。迁移页先准备身份映射和接入密钥，设备升级并配置密钥后才切换到新模型；明确提示该身份内代理/RDP 将自动可用。
4. 旧 RDP 显式授权是设备对设备的范围，不能自动升级为整个身份可用。迁移页按“目标设备 + 原访问设备所属身份”聚合为候选，列明影响范围，由管理员选择功能并确认后创建新记录；未确认的记录仅按 legacy 范围保留，映射不全不生效于新模型。清理“初始化自动删除 RDP 授权”的旧迁移与新迁移顺序关系，保证重复启动不清空新授权。
5. 服务端先支持 v4 和受控 v3 兼容，再升级桌面和 Android；v3 仅接受尚未迁移、已存在且已批准的 legacy 设备，按旧 owner 与 legacy 策略判断。已迁移设备必须使用 v4 和有效接入密钥；旧协议不能绕过密钥撤销或创建新身份归属。兼容期开关可关闭；v4 失败不自动降级绕过验证。
6. Android 从现有配置版本 2 迁移：保存已有默认出口、VPN 范围、端口及三个运行意图；初始生成与旧全局代理行为等价的空规则配置，不自动开启新功能。迁移引导只要求填入接入密钥，身份由服务端识别。
7. 新客户端遇到不支持清单的旧服务端可明确提示兼容模式并保留高级手填；新身份认证本身需要支持该协议的服务端，手填出口不能绕过这个条件。
8. 数据库回滚使用升级前备份；客户端规则配置保留可导出副本。不要用旧二进制直接写入已升级的授权数据库。

**十、验收矩阵**

| 范围 | 必测场景 | 预期 |

| 传输一致性 | Relay TCP/UDP、代理 P2P、RDP Relay/P2P、续租、连接恢复、测速 | 任一路径不能绕过相同策略 |
| 撤销/竞态 | 编辑/删除与开流并发、被授权身份多台设备的存量 UDP/P2P/RDP、取消单项、控制断线、授权过期、身份/设备删除、归属变更 | 被撤回功能的新连接立即拒绝；覆盖该身份全部设备的相关存量连接；保留功能继续有效，重连不能恢复旧权利 |
| 清单 | 同身份、已共享、未知目标、自身出口、离线、重名、改名、删除、撤销、多个默认候选 | 无越权枚举；稳定 ID；不悄悄改出口 |
| 规则 | 顺序、启停、OR/AND、默认动作、组合应用/IP、IPv4/IPv6、域名与真实 IP、端口/协议 | 命中与动作符合展示；拒绝不经地址重试绕过 |
| 应用分流 | 两应用同一目的地、TCP/UDP、多 association、共享 UID、未知 UID、包不可见/卸载、工作资料 | 不串应用、不串出口；有边界提示与可诊断失败 |
| Android 8/9 | IP/端口/域名规则、导入含应用条件的配置 | 已支持规则正常；不静默扩大应用规则范围 |
| DNS | Mapped DNS、真实 IP、DNS 出口离线、缓存换代、Private DNS、DoH/DoT、IPv6-only/DNS64 | 不误把合成地址当真实 IP；不静默绕回物理 DNS；记录不支持场景 |
| 设置 | 子页连续保存、取消、旋转、后台恢复、规则更新、需要重建的配置 | 不覆盖其他页、不丢运行意图、不产生第二个 Core |
| 迁移 | 新库、已有库、管理员审批多人的设备、旧设备对设备授权转为设备对身份授权、重复升级、旧/新客户端共存 | 无误归属；授权扩大到身份需明确确认；无重复迁移清空授权 |
| 回归交付 | VPN/本机代理/出口共存、Wi-Fi/蜂窝切换、P2P 回退、arm32/arm64、16 KB 页、连续启停及长时负载 | 构建和真实运行均有记录；资源、功耗和错误情况可审阅 |
