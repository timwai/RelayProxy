# 设备分组与统一出口选择

状态：交互设计草案，尚未实现。2026-10-26。

## 产品约定

设备中心增加“设备分组”。一台 Agent 设备可属于多个分组；每个分组保存名称、稳定 ID 和有序成员列表。首版不嵌套分组。局域网中未安装 Agent 的电视、游戏机等仍通过来源 IP / CIDR 匹配规则，不作为代理出口成员。

用户已确认组内采用 **按优先顺序、故障时切换**。分组可在所有能够指定 Agent 出口的位置选用，包括默认代理出口、分流规则出口、DNS 出口、网关默认出口，以及后续新增的同类入口。

## 交互

- 设备中心提供“设备”和“设备分组”两个视图。设备列表可设置所属分组；分组列表显示成员顺序、可用数量、当前首选成员与引用位置。
- 新建 / 编辑分组时勾选成员，用上移 / 下移调整顺序。名称不能为空、不能重名，至少包含一个成员。
- 全部出口选择入口使用同一个选择器，按“设备分组”和“单台设备”组织选项。原有“跟随默认出口”“直连”等特殊选项保留其原有适用范围。
- 选中分组后显示“分组名 · 当前选用设备”；连接详情同时记录配置的分组与该连接最终使用的设备。
- 分组重命名后所有引用自动显示新名称，引用使用稳定 ID。成员与顺序变化对所有引用处的新连接统一生效。
- 删除已被引用的分组前必须移除引用，界面列出可跳转的位置。设备离线不移除成员；成员全部不可用时保留配置并显示原因。

## 选用语义

1. 分流规则只执行一次，得到动作与出口目标。目标可为单台设备或设备分组。
2. 分组按顺序筛选当前入口可使用的成员：在线、开启出口、具有现有访问权限，并支持该次连接所需的协议与能力。
3. 新连接先尝试第一个可用成员。明确的链路 / 建连失败可在尚未交付应用数据时尝试下一成员；不重复发送已有应用请求，不迁移存量 TCP 连接。
4. 每个 UDP 关联固定到选定成员，避免同一关联的数据在不同出口间往返。成员故障时结束受影响的关联，后续新关联重新选择；不以普通 UDP 无响应直接判定出口失效。
5. 首选成员恢复并通过健康稳定判定后，新连接重新优先使用它。存量连接保留原出口。
6. 所有候选不可用时，触发对应功能已有的故障策略。分组本身不引入隐式 DIRECT；网关默认阻断 PROXY。身份或 ACL 拒绝不触发故障直连，也不放宽任何成员的权限。

DNS 出口切换时，上游连接和解析缓存按实际出口作用域隔离。可用性取决于上下文，某个分组在 TCP 入口可用，不代表它在要求 UDP 的入口也可用。

## 统一数据模型

实际落地采用保留前缀的稳定引用，兼容已有单设备字符串配置，不增加新的 Server 分组协议：

```yaml
proxy:
  default_exit_id: group:asia
routing:
  device_groups:
    - id: group:asia
      name: 亚洲出口
      members: [agent-tokyo, agent-singapore]
  dns_exit_id: agent-home
```

`group:` 由统一拨号器在本地解析为实际 Agent ID，分组 ID 不会作为设备 ID 发送到 Relay。原有设备 ID、自定义出口 `local:`、空值及特殊出口语义保持兼容。配置包含分组时应使用支持本功能的新客户端，旧客户端不会解释 `group:` 引用。

分组随 Agent 本地配置保存，不增加审批流程；每次建连仍执行成员现有权限校验。拨号时取得不可变成员快照，一次建连中的重试顺序固定，配置修改影响后续拨号。

## 与网关设计的关系

网关复用现有分流规则和分流引擎，增加入口、来源 IP / CIDR 条件。网关页面保留运行概览、网络设置和来源设备，通过“查看适用规则”进入统一分流规则页面，不增加独立规则集。

网关默认出口也使用相同的 `group:` 引用。这里的“设备分组”表示候选出口设备集合，与未来可能引入的局域网来源 CIDR 分组是两个不同的条件，不能混用。

## 原型覆盖与后续验收

交互原型覆盖分组新建、重命名、成员维护、排序、引用保护，以及默认出口、DNS、统一规则、网关四类入口的相同选择器。设计控件可模拟首选设备离线，观察后续连接选用备选成员。

实际实现需要补充统一选择器入口清单，并验证旧配置兼容、TCP / UDP 能力过滤、候选建连失败、首选恢复、全部不可用、引用删除与配置并发更新。当前原型仅演示界面和本地状态，不证明网络故障切换已经实现。


## 实现验收

本仓库已实现 Windows、macOS、Linux 和 Android 的公共分组拨号、配置与 UI；Linux 网关通过独立 namespace 的透明 TCP/UDP、UDP/TCP DNS、来源限制、IPv6 阻断、停止阻断、重启与关闭清理测试。部署方法和实际 YAML 见 [使用说明](gateway-and-groups-usage.md)。原型阶段提出的独立健康稳定窗口和具名 `ExitTarget` 序列化未采用；首期由实时在线授权清单和实际建连结果判断可用性，每次新连接重新优先首成员。
