# RDP 长时间卡住与重连修复

日期：2026-10-19。针对「只有远程桌面卡住，RelayProxy 仍在线」排查并修复三个代码问题；尚未在故障机器上验证实际触发原因。

## 已修复的问题

| 问题 | 原行为 | 修改后 |
| --- | --- | --- |
| 主 TCP 通道空闲误回收 | 中继沿用普通代理的 5 分钟空闲回收；Agent 两端为 10 分钟；目标直连和公网入口为 30 分钟。TCP 安静期间的 UDP 活动不刷新这些计时器 | 五处 RDP 转发均随端点关闭或会话取消结束，保留握手超时、TCP 保活和授权租期约束；普通代理的空闲回收规则不变 |
| 一次续租失败导致断开 | 单次控制请求超时或暂时失败，立即关闭直连会话和本地 RDP 监听，即使数据通道正常且租期仍有效 | 正常续租间隔为租期的三分之一，至少 5 秒；临时传输故障或 `AUTH_UNAVAILABLE` 在原租期内每秒重试；请求期限不超过原租期。明确拒绝立即关闭，未获得有效 ACK 不延长租期 |
| UDP 直连静默失效无法发现 | 发送保活但丢弃 ACK，不检查对端是否响应；UDP 写入仍成功时，读取可能一直阻塞 | 校验保活 ACK 的来源、HMAC、会话和待确认 nonce，仅接受一次。有效数据也计入活跃；连续三个保活间隔无认证回包时关闭关联，唤醒读取，后续本地数据触发现有重建及中继竞速 |

RDP 主连接使用 TCP，UDP 是额外的多传输通道，因此单独观察 TCP 空闲不能判断桌面会话是否结束：[Microsoft RDP Channels and Multitransport Connections](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpemt/4d98f550-6b0d-4d5f-89f5-2ac8616246a2)。

UDP 保活继续每 10 秒发送，失效检查按相同周期执行，通常在最后有效回包后约 30–40 秒触发。该机制提供故障退出与重建入口，不能保证网络中断时画面不中断，也不迁移已经断开的 TCP 连接。

## 验证

新增用例覆盖：

- 模拟时钟推进 31 分钟，控制端和中继的安静 TCP 通道仍能双向传输；会话取消后资源释放，转发计数正常。
- 临时续租失败恢复、请求阻塞、错误或过期 ACK、授权撤销；确保失效重试不会延长原授权。
- UDP 静默丢包唤醒读循环，健康空闲路径通过 ACK 保持；错误来源、会话、HMAC、nonce 和重放 ACK 不能延长存活。

相关包通过并发检测：

```sh
go test -race ./agent/rdp ./agent/rdp/p2p ./internal/p2p/punch ./server/gateway ./server/rdp ./agent/app ./agent/client ./internal/tunnel -count=1
```

以 Go 源码 overlay 运行修改前版本，新增用例可复现控制端和中继 TCP 误关闭、续租过早断开、UDP 静默失效后读循环持续阻塞。检查期间没有替换工作区源码。

## 上线与实机验证

需更新控制端 Agent、目标端 Agent 和 Relay 服务端，才能消除整条路径上的旧计时器。此次修改未部署到正在运行的实例。

更新后验证：持续操作及保持桌面静止超过 30 分钟、UDP 直连丢包后继续输入、中继正常但续租请求短暂超时。观察 RDP 的 TCP/UDP 路径与 `[RDP]` 日志；授权撤销和真正的租期到期仍应结束会话。
