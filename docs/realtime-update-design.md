# RelayProxy 实时更新统一机制（2026-10-12）

## 1. 已有能力与问题

现有 **Agent** 通过 QUIC/TLS 长连接完成身份认证。Server Gateway 的授权变更在随后的设备心跳中重新检查，原生代理出口、RDP 目标通过 Ping/Pong 返回；出口库存发生变化时，对声明了 `resource_inventory_push_v1` 的 Agent 还能以专用 Stream 主动推送清单修订号。心跳默认 15 秒，接收方在网络断开后重建会话并重新拉取状态。这已经是事件通知 + 最终一致性核对，而不是每个页面各自轮询。

以前 Server React 大部分数据仅在页面加载、手动刷新、当前浏览器发起写操作时更新；Browser Sync 管理页单独 15 秒轮询在线状态，审批与规则表不会在其他管理员操作后立即刷新。Chrome 已批准设备拥有已认证的 WSS 推送，但**等待审批的设备不能使用 WSS**，只能用显式提交的待审批身份安全地查询注册状态。Chrome 设置界面原先每 8 秒询问本地 worker 连接状态。

## 2. 跨端统一的逻辑协议

统一 **INVALIDATE → REFETCH → RECONCILE**，不强制不同网络端使用同一种物理传输。

| 传输 | 订阅鉴权 | 快速失效信号 | 断线/漏事件补偿 |
| --- | --- | --- | --- |
| Agent QUIC 控制面 | Agent 身份 ID、设备私钥、Server 签名审批 | 已有出口库存专用流 | Ping/Pong 心跳和 QUIC 重连 |
| Server Web SSE | 当前已登录管理账户 Session Cookie | `event: invalidate` + 递增 revision，不含资源内容 | EventSource 重连时全量重读、页面重新可见时重读、45 秒兜底 |
| Browser Sync Chrome 待审批 | 用户已点击提交的 Origin、设备 ID、身份 ID、名称及现存设备密钥 | 不允许开未审批 WSS，已有注册 HTTP 接口低频检查 | Chrome Alarm 约 60 秒（Chrome 调度可能延后），待审批标记持久化 |
| Browser Sync Chrome 已批准 | 服务端挑战 + 浏览器私钥 ECDSA 证明 | 既有签名 WSS，会话/ACK/规则控制；本地连接状态变化触发 `chrome.storage.onChanged` | WSS 重连、ACK 查询、Alarm、页面聚焦和本地 60 秒兜底 |

事件只是 **提示本地缓存失效**，最终权限/出口/规则/状态由服务端授权 API 或已认证的设备协议重新判断。不要把 SSE 或本地存储提示当成审批凭证。

## 3. Server SSE 安全约束

新端点：`GET /api/v1/live/events`，经过 Server 原本的 `requireAuth`；连接限额 128；保持心跳 25 秒，并在每次心跳时复查当前登录账户是否仍处于激活状态及角色/身份是否改变。没有事件正文中的设备 ID、身份 ID、网站 URL、公共/私钥、Cookie、Payload、Token 或管理操作参数。

匿名 Browser Extension 注册成功后仅向管理员发出刷新提示；已认证管理 API 成功写入后推送相应可见范围的刷新提示；Agent 会话 Register/Unregister/Reap/身份撤销后也发出事件。管理员可以收到全局事件；身份账号只能收到归属于该身份的事件，管理员的全局操作不会通过 SSE 暴露其他身份的操作时间。订阅通道单槽缓存，慢客户端最多积压一个刷新提示，不会阻塞审批或 Agent 数据流。

Server Web 所有订阅者共用一个 `EventSource`，180 ms 合并重复提示，立即通过已有 Cookie 鉴权的 REST API 刷新自己可见的资源；页面隐藏时不会周期性请求。原配置表单仍保护未保存编辑，不被实时更新覆盖。

## 4. 不能混淆的边界

- **待审批设备无实时 WSS 推送**，这是安全设计，不是遗漏按钮。若要做到审批后毫秒级连接，需独立设计预审批的签名长轮询、挑战身份和权限隔离，不应允许匿名设备订阅管理 SSE。
- 15 秒 Agent 心跳不表示所有 Server Web 图表都达到 15 秒采样分辨率；高频带宽、流量、延迟采样与低频权限变更应采用不同采样预算，避免将大流量监控数据推送给所有管理网页。
- Browser Sync 已连接端 WSS 的 SESSION/ACK 依旧遵守 E2EE、回放/规则 ACL；SSE 只负责 Server Web 失效通知，不能跨协议作为会话内容传输通道。
- 单机内存事件总线不直接支持多实例管理节点间广播；如果未来拆成多个 Server 实例，需通过共享事件日志或具备顺序号的消息总线传播。
- 事件可能在重连、进程重启、代理缓冲或订阅容量达到限制时遗漏，因此任何读取端必须保留可证明安全的最终一致性补偿；不会保证每一条中间变化都展示。

## 5. 后续验收

P0：受限身份隔离、无内容事件、慢订阅者不阻塞 API、注册审批触发、Agent 会话增删触发、SSE 浏览器重连后强制刷新、配置有未保存更改时保留用户编辑、Chrome 待审批仍不能直接发起 WSS。

实网：Nginx/Caddy SSE 不缓冲与 keepalive，旧 Server 版本无 SSE 时的兜底刷新，多个管理员客户端并发操作、注销/账户停用后的长连接清理，Agent 快速断线重连，弱网后台 MV3 Alarm 调度和 24 小时稳定性。
