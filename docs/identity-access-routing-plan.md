# 身份隔离、设备授权与 Android 分流实施规划

更新日期：2026-10-04

## 1. 最终需求

1. Server 创建身份。身份类似租户，只负责数据和访问边界，不包含任何设备能力。
2. Server 为每个身份自动生成 16 位小写字母数字身份 ID，仅用于设备连接和隔离。
3. Agent 和 Android 连接时填写身份 ID，不使用身份接入密钥；身份使用管理员自定义的用户名和独立密码登录 Server Web。
4. 设备继续使用本机生成的 Ed25519 安装私钥完成 challenge/proof，证明是同一个安装实例。
5. 新设备首次连接进入所属身份的待审批列表；该身份管理员勾选设备能力后才能上线。
6. 同一身份的已审批设备可直接使用彼此提供的出口和 RDP，双方仍必须具备相应设备能力。
7. 跨身份访问在目标设备上管理：目标设备所属身份可向某个身份授权 `proxy.use`、`rdp.connect`，支持创建、编辑、删除和过期时间。
8. Agent 可从服务端下发的已授权设备中直接选择出口。
9. Android 支持多个规则、应用与 IP/域名等条件，以及逐规则下拉选择出口。Android 8/9 保留非应用规则，应用分流限 Android 10+。
10. Android 设置按连接、出口、代理、VPN、规则、网络策略等页面拆分。
11. 消息渠道属于具体身份；渠道的兜底设备、内容分流目标、“全部设备”和消息历史都必须限制在该身份边界内。

## 2. 核心模型

### 2.1 身份

身份字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 服务端内部不可读 ID |
| `short_id` | Server 自动生成的 16 位小写字母数字连接 ID，不作为登录用户名 |
| 登录用户名 | 管理员创建身份时自定义，可与身份 ID 完全不同 |
| `name` | 显示名称 |
| `status` | `active` / `disabled` |
| `policy_revision` | 身份名称、状态等隔离策略的并发版本 |

身份不保存 Client、Exit、RDP 等能力。数据库中旧 `identities.capabilities` 列只为兼容已有 SQLite 文件保留，创建时固定写入空数组，运行时不读取。

创建身份时原子创建：

- 身份记录；
- 独立用户账号；
- `identity_memberships` owner 关系。

禁用身份会同步禁用该身份账号，并使该身份的设备会话失效。

### 2.2 设备

设备由以下信息唯一识别和验证：

- installation ID；
- Ed25519 公钥和指纹；
- 设备名称、平台、版本；
- 声明能力；
- 服务端批准能力；
- 所属身份；
- `pending`、`approved`、`rejected`、`revoked` 状态。

设备能力包括：

| 能力 | 用途 |
| --- | --- |
| `proxy.client` | 发起代理流量 |
| `proxy.exit` | 提供出口 |
| `rdp.controller` | 发起 RDP |
| `rdp.host` | 提供 RDP 主机 |
| `rdp.public` | 允许创建公网 RDP 入口 |

设备声明能力用于申请服务端授权；会话数据面的有效能力始终是“服务端批准能力 ∩ 本次客户端运行能力”。客户端重连不能自行扩权，本地关闭的功能也不会因为历史批准而继续对外提供。

Android 在连接设置保存后、客户端打开时及设备重启后建立控制连接，预先声明 `proxy.client` 与 `proxy.exit`，使设备审批和授权出口清单在点击启动前就能完成。启动出口、VPN 或本机代理只切换运行能力；控制连接不会让未启动的 Android 被登记成在线出口。已审批设备后来声明新能力时，服务端为尚未批准的能力重新生成 pending 申请；原有批准能力继续有效。批准新增能力时合并到同一设备，不创建第二台设备，也不覆盖之前的能力。

### 2.3 跨身份授权

`device_identity_grants` 表示“一个目标设备向一个访问身份开放哪些功能”：

| 字段 | 说明 |
| --- | --- |
| `target_device_id` | 提供出口或 RDP 的具体设备 |
| `grantee_identity_id` | 获得访问权的身份 |
| `features` | `proxy.use`、`rdp.connect` 的非空集合 |
| `expires_at` | 可选过期时间 |
| `revision` | 编辑、删除的乐观锁版本 |

约束：

- 同一目标设备与获授权身份只允许一条记录；
- 同身份访问无需显式记录；
- 授权方只能管理自己身份下的目标设备；全局管理员可管理全部设备；
- 更改目标设备的身份归属时删除该设备已有跨身份授权，避免授权跨越新的所有权边界；
- 创建、修改、删除授权后立即清理受影响的 Relay、P2P 和 RDP 路径。

Server 自身作为出口使用独立的 `system_identity_grants`，仍由全局管理员管理。

## 3. 设备连接协议

当前设备身份协议为 v5：

1. 客户端发送 16 位身份 ID、安装 ID、公钥、客户端 nonce、设备元数据、声明能力和传输能力。
2. Server 只按 `short_id` 解析启用中的身份，生成带服务端实例 ID、服务端 nonce 和过期时间的 challenge。
3. 客户端用安装私钥签名。签名载荷绑定协议版本、身份 ID、安装 ID、公钥、双方 nonce、服务端实例、设备元数据和能力声明。
4. Server 验证签名后重新检查身份状态和设备绑定。
5. 首次出现的安装身份写入该身份的 pending 申请，不创建设备能力授权。
6. 身份管理员批准后创建设备，并勾选批准能力；客户端重连后上线。
7. 已审批设备新增能力声明时，只把未批准部分写入 pending；审批后合并能力并使旧会话失效，客户端重连获取新授权。
7. 已批准设备仅在公钥、安装 ID、设备 ID、所属身份和启用状态全部匹配时重连。

身份 ID 不是认证秘密，可以在明文 TCP 中传输；公网环境仍建议启用 TLS 保护业务流量。安装私钥不离开客户端。

生产 Server 默认拒绝 v3。Agent 和 Android 不再因身份 ID 为空而降级；缺少或格式错误的身份 ID 会直接失败。

## 4. 授权判定

### 4.1 代理出口

允许 Client 设备使用目标 Exit 需要同时满足：

1. Client 已批准 `proxy.client`；
2. Exit 已批准并在本次会话声明 `proxy.exit`；
3. 两台设备同身份，或 Exit 的设备授权中包含 Client 身份的 `proxy.use`；
4. 授权未过期；
5. Relay ACL、目标 Exit 本地 ACL 和网络范围均允许；
6. 打开每条 Relay/P2P 流时重新查询实时策略。

### 4.2 RDP

允许 Controller 连接目标 Host 需要同时满足：

1. Controller 已批准 `rdp.controller`；
2. Host 已批准并声明 `rdp.host`；
3. 两台设备同身份，或 Host 的设备授权中包含 Controller 身份的 `rdp.connect`；
4. 授权未过期；
5. 每次连接和直连路径建立时重新查询实时策略。

公网 RDP 入口不是设备间授权，由 `rdp.public` 和全局管理员配置共同控制。

## 5. Server Web 与 API

### 5.1 身份管理

全局管理员可：

- 输入自定义登录用户名、显示名称和初始密码创建身份；身份 ID 由 Server 自动生成；
- 修改名称和启用状态；
- 重置身份登录密码；
- 为历史设备显式分配或更改身份。

身份登录后只看到所属身份的数据和设备，不显示全局设置或其他身份的私有设备信息。

### 5.2 设备审批与能力

身份管理员可：

- 查看所属身份的 pending 申请；
- 勾选申请中声明的设备能力并批准；
- 拒绝申请；
- 编辑所属设备的批准能力；
- 撤销或删除所属设备。

### 5.3 设备上的跨身份授权

打开一台已批准且具备 `proxy.exit` 或 `rdp.host` 的设备时，设备详情显示授权编辑器：

- 下拉选择被授权身份；
- 勾选“使用代理出口”和/或“连接 RDP”；
- 可选过期时间；
- 支持保存、编辑、删除；
- 同身份选项提示无需授权；
- 编辑和删除携带 revision，冲突返回 409。

主要接口：

| 接口 | 权限和作用 |
| --- | --- |
| `POST /api/v1/identities` | 全局管理员原子创建身份和登录账号 |
| `PATCH /api/v1/identities/{id}` | 全局管理员修改名称或状态 |
| `PUT /api/v1/identities/{id}/password` | 全局管理员重置身份密码并撤销旧 Web 会话 |
| `GET /api/v1/identity-options` | 已登录用户读取创建授权所需的启用身份选项 |
| `GET /api/v1/enrollments` | 按当前身份过滤待审批设备；管理员可看全部 |
| `POST /api/v1/enrollments/{id}/approve` | 当前身份范围内批准设备并选择能力 |
| `POST /api/v1/enrollments/{id}/reject` | 当前身份范围内拒绝设备 |
| `PUT /api/v1/devices/{id}/capabilities` | 编辑自己设备的能力 |
| `POST /api/v1/devices/{id}/revoke` | 撤销自己设备 |
| `DELETE /api/v1/devices/{id}` | 删除自己设备及相关关系 |
| `GET /api/v1/device-identity-grants?targetDeviceId=...` | 读取指定目标设备授权 |
| `POST /api/v1/device-identity-grants` | 为自己的目标设备创建身份授权 |
| `PATCH /api/v1/device-identity-grants/{id}` | 编辑授权功能、身份或过期时间 |
| `DELETE /api/v1/device-identity-grants/{id}?revision=...` | 删除授权 |

非管理员访问其他身份设备时统一返回 404，避免泄露设备是否存在。

### 5.4 消息渠道与消息历史

- 每个消息渠道保存唯一的 `identity_id`；身份账号只能列出、创建、编辑和删除自己的渠道，全局管理员可管理全部渠道。
- 全局管理员创建渠道时必须选择所属身份；身份账号创建渠道时由服务端从登录主体强制写入所属身份，客户端提交其他 `identity_id` 不生效。
- 渠道的固定设备、内容分流规则目标和 `allDevices` 都只在渠道所属身份内解析；`allDevices` 表示“该身份下全部已批准设备”，绝不表示全站设备。
- 公开 `/api/v1/push/{channelId}` 先解析渠道身份，再解析目标设备；未绑定身份的历史渠道拒绝投递，避免升级后继续全局广播。
- 消息记录持久化 `identity_id`，身份账号读取消息历史时直接按身份过滤，即使渠道后续删除也不会失去消息的隔离归属。
- 历史渠道迁移只在归属可唯一推断时自动补齐身份；多身份环境中无法判断归属的渠道保持未绑定，由全局管理员重新指定。

## 6. 历史设备迁移

1. 生产 Server 统一拒绝 v3，旧客户端必须升级。
2. Server 启动时为使用旧格式 ID 的现有身份生成新的 16 位身份 ID，保留其登录用户名、密码、设备和授权关系；管理员需要把新 ID 更新到客户端配置。
3. 旧设备不会按原 `owner_user_id` 自动推断身份，因为同一审批管理员可能管理多个隔离空间。
4. 全局管理员在设备管理中显式分配身份；现有设备 ID 和批准能力保持不变。
5. 分配后，客户端配置相同身份 ID。相同安装 ID、公钥和指纹重连时复用原设备，不重复审批。
6. 使用其他身份 ID 重连返回身份冲突。
7. 未分配身份的历史设备不能通过 v5 连接。
8. 删除设备会清除安装身份；再次连接会在指定身份下生成新的 pending 申请。撤销设备则保留安装身份并持续拒绝重连。

## 7. Agent

- 连接设置使用 `device.identity_id`；GUI 校验 Server 生成的 16 位小写字母数字格式。
- 不再读取环境变量或本地身份接入凭据文件。
- Server 下发当前设备可用的出口清单，GUI 通过下拉框选择默认出口。
- 规则可以覆盖默认出口；每次建流仍由 Server 校验实时授权。
- 身份待审批、拒绝、撤销、冲突和无效 ID 显示明确状态。

## 8. Android

### 8.1 页面拆分

设置目录分别进入：

- 连接设置；
- 出口节点；
- 本机代理；
- VPN 与应用范围；
- 分流规则；
- 网络策略。

各页面只保存自己的字段。规则使用独立 revision，避免旧页面快照覆盖其他页面的更新。

### 8.2 规则模型

每条规则包含：

- 启用状态和名称；
- 动作：`DIRECT`、`PROXY`、`REJECT`；
- 可选出口设备；
- 应用包名集合；
- 域名、IP、CIDR 或 IP 范围；
- 端口或端口范围；
- TCP/UDP 协议。

按顺序匹配第一条启用规则，未命中时使用默认动作。默认出口和逐规则出口都从服务端授权清单下拉选择。

Android 10+ 支持应用归属条件。Android 8/9 保留安装、连接、VPN 和非应用规则；保存包含应用条件的规则时明确拒绝。

### 8.3 运行时更新

- 有效连接配置会立即建立并后台维持控制连接，设备登记、审批状态和出口清单不依赖出口或 VPN 启动。
- “启动出口”和“启动 VPN”只启用对应数据面；未启动的设备即使已有 `proxy.exit` 授权，也不会进入服务端在线出口索引。
- 规则和默认出口热更新，只影响新流；已有 TCP 流不被强制中断。
- VPN 应用范围变化需要重建 TUN。
- 地址、身份 ID、端口、传输或物理网络变化需要重建 Relay 会话。
- 未知应用使用保护性 `REJECT` 元数据，不能静默落入其他应用规则。

## 9. 验收矩阵

| 范围 | 必测场景 |
| --- | --- |
| 身份 | 短 ID 格式/唯一性、独立登录、密码重置、禁用后 Web 和设备会话失效 |
| 首次接入 | 正确身份进入 pending；其他身份不可查看或审批；批准能力后才能上线 |
| 重连 | 安装签名、能力交集、身份冲突、拒绝/撤销、删除后重新 pending |
| 历史设备 | 显式分配后复用设备 ID 和能力；未分配拒绝；换身份拒绝 |
| 同身份 | 代理与 RDP 在设备能力齐备时直接使用；缺任一能力拒绝 |
| 跨身份 | 每设备创建、编辑、删除、过期；`proxy.use` 与 `rdp.connect` 相互独立 |
| 实时撤销 | Relay、P2P、RDP 在授权/能力/身份变化后清理现有路径 |
| Agent | 出口下拉、规则出口、待审批和错误状态、配置保存重启 |
| Android 10+ | 两应用相同目标走不同出口；TCP/UDP；IPv4/IPv6；共享/未知 UID |
| Android 8/9 | 非应用规则、VPN、配置迁移；应用规则明确拒绝 |
| 页面状态 | 旋转、后台恢复、取消、快速连续保存、并发 revision 冲突 |
| 消息渠道 | A/B 身份渠道互不可见；跨身份设备不可加入渠道或分流；`allDevices` 仅覆盖本身份；消息历史按身份隔离；未归属旧渠道拒绝公开推送 |
