# Android 极致省电优化（默认生效）

保留代理连接、原生 VPN 数据面、服务端推送和自动重连，仅减少无意义的前台服务定时唤醒、跨 Kotlin/Go 的读取和后台状态统计。不要通过关闭 TUN、请求电池优化白名单或禁用心跳来伪造省电效果。

## 实现

- **消息事件驱动**：Go Core 收到服务端推送后，通过 `MessageListener.OnMessage` 通知 Android；Service 合并待执行的 drain，取消每秒 `PopMessagesJSON` 轮询。回调不在 Go 的消息互斥锁内执行；注册前已经排队的消息也会触发通知。
- **Relay 状态采样**：前台 1 秒；后台亮屏 CONNECTING 10 秒、连接活跃 15 秒、空闲或其他状态 60 秒；息屏 CONNECTING 15 秒，其余 120 秒。网络和电源状态事件会要求即时刷新。
- **VPN 原生状态采样**：前台 1 秒、后台亮屏 30 秒、息屏 120 秒。只改变 `TProxyIsRunning` 和 `TProxyGetStats` 检查频率，不关闭 Hev、TUN 或 SOCKS5。恢复到应用前台或屏幕状态切换会主动采样。
- **已存在的 P2P 低功耗模式**：息屏、Doze、系统省电或移动网络时继续触发 `setPowerConstrained`；不改变网络优先策略、出口分流或代理 DNS 逻辑。
- **系统兼容**：未新增 WakeLock、AlarmManager、定时 WorkManager、忽略系统电池优化等权限。

## 出口 / VPN / 本地代理生命周期（第二阶段）

“已配置 Server 地址和身份”不再表示自动后台连接。Android 只在**连接配置有效**且至少一种业务显式开启时启动 Relay Core：

| 出口共享 | VPN | 本地 SOCKS5/HTTP | Relay Core / 心跳 / 网络监听 |
| --- | --- | --- | --- |
| 关闭 | 关闭 | 全关 | 完全停止，不留后台状态轮询 |
| 开启 | 关闭 | 全关 | 运行（提供出口共享） |
| 关闭 | 开启 | 全关 | 运行（提供 VPN 代理） |
| 关闭 | 关闭 | 至少开启一个 | 运行（提供本地代理） |
| 任意组合 | 任意组合 | 任意组合 | 只要还有业务开启就运行 |

具体同步路径：
- **手动开关**：关闭最后一个功能时，关闭旧 Core 并释放 NetworkBinder 的 ConnectivityManager 回调、停止 Relay 前台通知和状态刷新；其他功能仍开启则按新配置重建 Core。
- **启动/返回主界面**：`ACTION_CONNECT` 不能仅凭合法身份信息启动 Core，已有 Core 也不会因返回界面被无谓重建。
- **开机及升级重启**：BootReceiver 不再把存在有效配置当成自动连接条件；会恢复用户明确启用的出口、VPN 或本地代理。
- **设置保存**：不再强制保持或重新激活已关闭的所有业务；关闭最后一个本地代理时向旧 Relay Service 发送一次 `ACTION_RECONFIGURE` 以完成资源释放。
- **关闭 VPN**：只取消 VPN 的需求；`ACTION_RECONFIGURE` 让 Relay Service 决策，不能通过 `ACTION_STOP` 误清除用户独立开启的出口共享。
- **Android Always-on VPN**：系统要求恢复的 Always-on VPN 仍按 Android 原机制恢复，不受手动关闭全部业务策略误阻断。

**范围**：这是停止 Android 应用自己的 Core、心跳、网络监听与诊断刷新，并非声称 Android 系统不会执行任何电池/包管理活动。通知、网络流量和真实连接仍受系统 Doze、运营商及设备厂商后台策略影响。

## 第三阶段：事件合并与传输低功耗

- **心跳自适应**：系统省电、Doze、息屏，以及移动数据后台空闲时，Android 通过 `SetHeartbeatMultiplier(2)` 请求较低的心跳频率。Go Core 只允许倍率 1–2，实际间隔最大 60 秒；回前台/电源状态变化立即重新计算定时器。服务端仍使用原协商间隔的 `3 × heartbeatSec + 5s` 超时，避免无限制乘以 4 导致离线误判。QUIC 的默认空闲超时为 120 秒，因此不能直接使用 120 秒以上的心跳间隔。
- **通知状态合并**：仅对同一连接状态下的通知文案变化施加最短 2 秒更新间隔。实际网络状态从 CONNECTED 变 ERROR / WAITING_NETWORK 时即时显示，停止服务仍移除前台通知。
- **息屏保活不采集诊断计数器**：VPN 的 `TProxyIsRunning` 存活检查继续按既有退避策略执行；仅在应用界面可见且屏幕亮起时读取 `TProxyGetStats` JNI 计数器；返回前台后立即恢复采样。
- **按应用分流的正确性**：`getConnectionOwnerUid` 与应用规则匹配有关，不等同于 UI 监控。仅在 `routing.requiresApplicationIdentity` 为 true 时注册流量归属解析器；本阶段不在息屏强行跳过，否则可能将敏感应用流量错误发送至默认出口。
- **Doze 白名单 / WakeLock**：不在省电默认路径申请忽略电池优化权限或持有 WakeLock。这些措施可能增加电池消耗，并不保证系统、运营商或厂商 ROM 允许后台长期存活。若实际机型验证表明后台网络受限，应单独提供用户主动选择的稳定性指引和短时、有界的关键任务锁，而非默认打开。
- **Radio 请求合并**：应用层没有可安全合并的额外网络诊断请求；先以减少心跳小包作为蜂窝 radio 优化，后续需要抓包和 batterystats 数据才引入新的批处理策略，防止无意增加排队延迟。

## 第四阶段：按业务和到期时间唤醒

- **诊断不续期**：桌面和 Android 的 P2P 状态查询使用只读的 `PeekReadyForExit`，不再刷新最近业务使用时间；真实路由选择仍刷新时间，活跃流仍阻止空闲回收。
- **省电时按需直连**：启动、出口选择及心跳中的出口列表刷新只允许普通模式预热。省电模式下，出口上线和候选变化仍解除适用的失败冷却，但等待下一次业务请求才建立直连。首次请求可走 Relay，后续请求使用已准备好的直连；显式路径模式继续按原规则处理。
- **P2P 空会话休眠**：没有会话时停用空闲扫描计时器，没有会话和建连尝试时停用网络签名扫描计时器；会话增删通过广播唤醒两个维护循环。Android 关闭 Go 接口枚举扫描，使用既有 `NetworkBinder` 回调处理网络切换、地址、路由和 DNS 变化，并在绑定后重建传输。
- **UDP 按实际到期调度**：同一 QUIC 会话仍共用一个清理器，调度最近的碎片或空闲截止时间。仅依赖生命周期流的关联（例如 RDP）在没有待组装碎片时无需计时器；首个新碎片会唤醒调度。新关联、碎片和关闭事件按 100ms 窗口合并扫描，碎片仍在创建后 200ms 过期，双向读写使用单调时钟更新空闲期限，关闭与活动刷新用 CAS 防止并发复活。
- **只在界面展示 VPN 计数**：后台亮屏也跳过 JNI 流量统计；原生存活检查继续。屏幕关闭优先于可能尚未清除的 Activity 可见标志，避免息屏仍每秒轮询。

## 测试

1. Go：`go test ./...` 和相关包的 `go test -race`；新增覆盖 P2P 诊断不续期、空会话休眠/恢复、Android 省电心跳不预热但允许真实需求、UDP 碎片唤醒/释放、长短超时交错、双向活动续期与关闭后不复活。消息回调及切网保留本地代理的回归测试继续执行。
2. Android：执行项目构建脚本**重新生成** `mobilecore.aar`（`MessageListener` 是新增的 gomobile API），再执行 Android 单元测试 `PowerAwarePollPolicyTest` 、`CoreDemandTest` 及 `NotificationRefreshPolicyTest`；旧 AAR 无法通过新回调的 Kotlin 编译。
3. 启停组合：依次测试（出口、VPN、本地代理）的全部 8 种开关组合。关闭最后一个业务后，确认 Relay 通知消失、Core 已停止、没有定期状态刷新/重连；只开出口时从另一端访问出口；只开本地代理时验证 SOCKS5/HTTP；只开 VPN 时验证域名分流。快速连续开启/关闭不得保留僵尸连接。
4. 真机回归：前台、息屏、Doze 和 Wi-Fi ↔ 移动网络切换中检查 TCP、UDP、DNS、分流、VPN 保活、Relay 自动恢复。
5. 消息回归：在应用前后台、亮屏/息屏接收服务端验证码和重要消息，确认即时触发而非定时取消息；展示时间受 Android 通知与息屏策略影响。
6. 心跳兼容：验证 Server 15s 和 30s 协商值，在亮屏/息屏/Doze/蜂窝网多次切换后，持续 30 分钟确认设备不被服务端过早剔除，且退出 UI 后不丢必要的消息和出口会话。
7. 同型号同网络/同出口 A/B：各做至少 30 分钟无流量息屏待机和 30 分钟负载。通过 Android Studio Energy Profiler、`adb shell dumpsys batterystats --reset` / `adb shell dumpsys batterystats` 比较 CPU 唤醒次数、网络无线电活动时间、耗电估算，同时记录重连时延和消息时延。

**代价**：息屏时 VPN native 停止的检测可能延后最多约两分钟（不含 Android Doze 延迟）；VPN 转发本身不会因此停止。真正能减少多少电量要根据上述真机数据判断，不能由轮询次数直接换算。
