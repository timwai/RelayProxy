# 实际连接路径识别

实现日期：2026-10-30。

## 数据模型与兼容

保留现有 `path` / `transportPath` 枚举及文件传输回调，新增可选的 `ConnectionPath` 详情：

```json
{
  "path": "p2p_quic",
  "network": "lan",
  "transport": "quic",
  "localAddress": "192.168.1.10:50000",
  "remoteAddress": "192.168.1.20:51000",
  "interface": "en0",
  "candidateType": "host"
}
```

- `path` 表示连接机制：公网端点直连、P2P 协商直连或中继；保持原来的字符串。
- `network` 表示观察到的范围：`lan`、`public`、`virtual`、`loopback`、`unknown`。
- `transport` 表示实际承载协议，与业务的 TCP/UDP 协议分开。
- `candidateType` 匹配实际选中的对端端点：接口地址 `host`、反射地址 `reflexive` 或协商中学习到的新端点 `peer_reflexive`。不据此断言 NAT 类型或必然进行了穿透。

旧端不会因新增 JSON 字段而拒绝消息。新服务端接受缺少详情的旧报告；收到详情时校验枚举、路径一致性、地址格式和长度。详情只用于观察，不参与鉴权或修改路由策略。

## 识别与生命周期

握手或业务打开请求成功之后记录实际端点。基于选用的本地地址匹配接口：同网段普通接口记为 LAN，可识别的隧道/虚拟接口记为虚拟网络，普通接口上的公网对端记为公网。私网地址、CGNAT 地址或 `Type=lan` 候选本身都不足以证明局域网路径。

UDP 通配监听地址需要通过内核源地址选择补充本地接口证据，临时 UDP socket 不发送数据包。无法确定时保留 `unknown`。这是基于端点、地址前缀和接口标志/名称的尽力识别，并非逐跳路由追踪；自定义虚拟网卡名、特殊策略路由、NAT 回环等仍需结合实际环境判断。

- 代理 TCP/UDP：详情随实际选中的会话传入连接记录。复用同一就绪 QUIC 会话不会丢失原生 datagram 能力。
- TCP 断线恢复：原子切换路径与详情，恢复到中继时清除直连候选信息。
- 代理 QUIC 端点重绑定：读取元数据时验证端点是否变化，变化后清除旧网络范围/接口/候选判断，不在统计读取过程中发起探测。
- 历史记录：关闭时固定最后一次路径，停止引用活连接；返回快照不暴露可修改的内部详情指针。
- RDP：仅对竞速后被控制器接受的通道记账，TCP 多通道与 UDP 当前关联分别记录；通道关闭、关联替换后同步移除旧详情。
- 文件传输：认证成功的下载/上传尝试报告详情，重试切换到中继时更新任务；预探测只表示可用性。重启恢复任务时清除上次运行的路径信息。

## 展示

Agent 与 Server 的 React 界面共用路径名称格式化逻辑；Agent 的 Go-only 旧界面同步支持新详情。

可用直连状态与 `activeProxyPaths` 分开。后者来自当前出口已记录的活动代理连接，可以同时包含多个路径；没有业务连接时显示“暂无活动代理连接”，旧 Agent 未提供该字段时显示“未提供实际连接路径”。Server 路径分布分别统计单一路径、混合、空闲和未上报状态。

连接列表、RDP 通道和文件任务可显示“局域网直连 · QUIC”“P2P 公网直连 · UDP”“虚拟网络直连”“中继 · TLS”等；未确认的网络范围明确显示未知。

## 自审与验证

新增或扩展测试覆盖：

- IPv4 LAN、同链路公网 IPv6、公网、跨子网私网、CGNAT、VPN、回环与未知接口。
- 真实 P2P QUIC 会话的选中端点/候选信息能够透传到实际会话，datagram 能力仍在。
- 代理 TCP/UDP 的实际路径与备用直连状态独立；TCP 经中继恢复后的路径和历史快照一致。
- RDP 接受/关闭通道及 UDP 端点详情；文件打洞 QUIC 返回实际选中端点。
- 服务端报告校验与兼容；Agent/Server 界面的空闲、混合路径和旧数据处理。

执行相关 Go 模块的 `-race` 测试、`go vet`、Windows amd64 交叉编译、两个 React 项目的测试与生产构建以及 `git diff --check`。

本机自动化验证不等同于真实跨 NAT、跨网段或 Windows 实机验收。网络范围识别保持上述尽力判断边界。
