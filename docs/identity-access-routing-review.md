# 身份隔离、设备授权与 Android 分流自审记录

日期：2026-10-04。对应 [实施规划](identity-access-routing-plan.md)。

本轮按最终需求重新审查身份模型、设备接入协议、审批边界、跨身份代理/RDP 授权、历史设备迁移、Agent 配置以及 Android 配置与构建。当前身份只承担隔离职责；能力只存在于设备；Server 自动生成 16 位小写字母数字身份 ID，登录用户名由管理员独立设置；设备使用公开身份 ID 和本机 Ed25519 安装身份接入，首次连接必须由所属身份审批。

结构导航使用 codebase-memory Tier 2。图索引生成于 2026-10-02，覆盖检查显示本轮多个文件已变化或未被索引，因此所有结论均以直接读取当前源码、API/仓储/集成测试和实际构建为依据。

## 审查结论

| 范围 | 结论 |
| --- | --- |
| 身份模型 | 身份只保存自动生成的 16 位 ID、名称、状态和策略版本，不保存设备能力；创建身份时原子创建自定义用户名的独立登录账号和 owner 成员关系 |
| 接入协议 | v5 Hello 携带公开身份 ID，签名载荷绑定身份 ID、安装信息和声明能力；服务端默认拒绝 v3，不再签发或读取身份接入密钥 |
| 设备审批 | 新安装只创建所属身份的 pending 申请；已审批设备新启动出口或代理时只申请新增能力；审批合并到同一设备并刷新会话，不覆盖已有能力 |
| 同身份访问 | 代理和 RDP 在双方设备能力满足时直接允许，运行时仍检查在线声明、ACL 和实时策略 |
| 跨身份授权 | 授权挂在具体目标设备上，按身份授予 `proxy.use`、`rdp.connect`，支持创建、编辑、删除、过期和 revision 冲突检测 |
| 管理权限 | 身份账号只能管理本身份设备及其授权；访问其他身份设备统一返回 404；禁用身份会撤销其 Web 与设备会话 |
| 历史设备 | 不根据旧 `owner_user_id` 推断身份；管理员显式分配后保留设备 ID 和批准能力，并把管理权同步给身份登录账号 |
| Agent | 使用 `device.identity_id`，不保存身份接入凭据；可从服务端授权清单选择默认出口 |
| Android | 保存公开的 16 位身份 ID，保留多页面设置、多个应用/IP/域名规则以及默认/逐规则出口选择；应用归属限 Android 10+ |

## 自审发现并修复的问题

| 优先级 | 问题 | 修复与证据 |
| --- | --- | --- |
| P1 | v5 Gateway 仍无条件要求旧 `AuthorizeDevice` 回调，正式配置会在挑战前拒绝全部身份 ID 客户端 | 只在显式 legacy 模式校验旧回调；Agent/Gateway 集成测试通过 |
| P1 | 历史设备分配身份后仍保留旧审批管理员为 owner，身份账号看不到也无法管理该设备 | 分配身份时同步到身份 owner 账号；同一身份重复保存也会修复旧数据；仓储迁移测试覆盖设备 ID、能力、owner 和身份冲突 |
| P1 | 非管理员刷新设备列表时清空当前设备授权状态，导致设备内授权编辑器丢失数据 | 保留当前设备授权状态并在打开设备时按目标设备重新加载；API 生命周期测试覆盖身份账号只能管理自己的设备授权 |
| P1 | 禁用身份仍可作为授权方或被授权方创建新跨身份授权 | 创建和修改授权时同时要求目标身份与被授权身份处于 active |
| P1 | 身份密钥与 TLS 限制残留在 Agent、Android、协议、API 和文档，和公开身份 ID 模型冲突 | 删除凭据存储包、环境变量、桥接接口、服务端密钥 API 和对应 UI；源码检索不再存在相关类型、接口、配置或环境变量，文档只描述该机制已移除 |
| P1 | 身份 ID 与登录用户名仍是同一个可人工指定字段，不符合连接标识自动生成和账号独立命名的要求 | Server 使用加密随机数生成 16 位小写字母数字组合；创建及重置登录配置接受独立用户名；旧格式 ID 启动时自动换发且保留账号、设备和授权关系 |
| P1 | Android 首次只批准出口或代理后，启动另一项只刷新声明能力，不会重新进入待审批，导致第二项无法批准 | 已审批设备把“本次声明 − 历史批准”写为增量 pending；审批合并能力并原子失效旧会话；仓储和 API 测试覆盖仅新增能力、保留原能力、拒绝不撤销设备和会话刷新 |
| P1 | Android 14+ 在 VPN 尚未建立时以 `systemExempted` 类型启动前台服务，设备不满足系统豁免条件时会直接抛出异常 | VPN 前台服务改为无运行时前置条件的 `specialUse` 并声明具体用途；Service 和 Activity 两层捕获启动异常并展示错误；Lint、单测和 APK 构建通过 |
| P1 | Android 按应用归属补丁从 Hev 用户态协程栈直接进入 ART JNI，首个 TCP/UDP 流量可能触发 Java 无法捕获的 native 进程退出；native 状态轮询还会与停止并发 | UID 查询改由独立的 ART daemon pthread 执行，Hev 线程只通过条件变量同步请求；全部 TProxy JNI 调用收敛到 VPN 单线程执行器；双 ABI native 编译和 APK 构建通过 |
| P2 | 首次设备申请缺少身份范围，身份用户可能看到或审批其他身份的申请 | enrollment 保存 `identity_id`，列表、批准、拒绝全部按登录身份过滤 |
| P2 | 身份状态变化和密码重置后已有 Web/设备会话仍可能继续使用旧权限 | 密码重置撤销该身份 Web 会话；身份禁用同步账号状态并失效该身份设备会话 |
| P2 | 移动目标设备到新身份时，旧跨身份授权可能跨越所有权边界 | 身份变更事务内删除该目标设备授权并记录审计，随后清理受影响的 Relay、P2P 和 RDP 路径 |

## 尚需设备验收的边界

- 没有连接 Android 真机或模拟器，因此 VPN 前台启动修复，以及 Android 10+ 的真实 UID/包名归属、TCP/UDP、IPv4/IPv6、共享 UID 和应用卸载场景仍需设备验收。
- Android 8/9 已保留 API 26 最低版本和非应用规则，但安装、VPN、升级迁移及应用规则明确拒绝仍需真机验证。
- Agent 与 Server Web 的表单和状态流已通过编译、语法与 API 测试，仍需人工验证完整交互、错误提示和不同窗口尺寸。
- 真实 RDP 客户端、跨网络 P2P、授权撤销时已有长连接的用户体验以及正式签名 Android 包仍需发布前验收。

代码层面的最终模型和自动化回归已闭环；上述事项属于需要真实设备、网络或发布凭据的验收范围。
